# Windows packaging layout

生成安装包分三步：`Build-Client.ps1` 编译原生程序，`Prepare-PackageFiles.ps1` 把编译输出按安装布局暂存到本目录，`Compile-Installer.ps1` 调用 Inno Setup 编译 `msime_setup.iss`。安装器只读暂存目录，不读源码树。

`Prepare-PackageFiles.ps1` 写出这些输入：

| Staging path | Contents |
| --- | --- |
| `tsf_dll/32` and `tsf_dll/64` | `MetasequoiaImeTsf.dll` and matching symbols, the host DLL, and the runtime DLLs beside the 32-bit TIP (the x64 ones by the same names); the installer also puts the `tsf_dll/64` host and runtime DLLs into the Server folder, so `server_exe` does not carry them |
| `tsf_dll/arm64` | Arm64X `MetasequoiaImeTsf.dll`, its PDB and the ARM64 host DLL, used only on Windows on Arm |
| `server_exe` | Windows Server, native WinUI 3 `msime-client-settings.exe`, the watchdog, the preparation tool, and native resources |
| `app_data` | default configuration, helpcode tables, prompt sounds and, when generated, built-in sound packs |

Native CMake targets come from the configured Windows build directory (`target/windows-full/<arch>` for full and `target/windows-<id>/<arch>` for another edition, as produced by `../Build-Client.ps1 -Edition <id>`). `Prepare-PackageFiles.ps1 -Edition <id>` takes that edition's host DLL name, resource lock and language dictionaries from `shared/contracts/editions.json` and writes `server_exe/edition.json` for an edition other than full; `Compile-Installer.ps1 -Edition <id>` passes `/DEdition=<id>` to ISCC, and `editions.iss` (generated by `../scripts/edition_windows.py gen`) supplies that edition's AppId, install directory, registry key, watchdog task and installer name. Without `/DEdition` the script compiles full exactly as before. The TSF DLL remains an in-process component and the Server remains out of process; packaging them together does not change that boundary.

## 本机生成安装包

先准备 x64/x86 原生依赖前缀（见 `../Build-Client.md`），安装 Inno Setup 6.6 或更高版本，并让 CMake、Cargo、MSBuild 在 `PATH` 上。以下命令在仓库根目录、普通 PowerShell 中执行；`-Edition pinyin` 可换成 `full`。

```powershell
# 1. 按版本资源锁下载词库到 target/desktop-resources（已匹配的不会重复下载）
python scripts/fetch_desktop_resources.py --edition pinyin

# 2. 编译 x64/x86/Arm64X 原生程序和 Rust 宿主 DLL
.\platforms\windows\Build-Client.ps1 `
  -X64Dependencies C:\deps\x64\x64-windows `
  -X86Dependencies C:\deps\x86\x86-windows `
  -Edition pinyin

# 3. 收集第三方声明（输出 target/windows-notices，Prepare 会自动找到）
.\platforms\windows\Collect-Notices.ps1 `
  -DependencyPrefixes C:\deps\x64\x64-windows, C:\deps\x86\x86-windows `
  -Edition pinyin

# 4. 暂存安装文件并写入版本号
.\platforms\windows\installer\Prepare-PackageFiles.ps1 -Edition pinyin

# 5. 用 Inno Setup 编译安装包，输出在 installer\Output
.\platforms\windows\installer\Compile-Installer.ps1 -Edition pinyin
```

这一步产出的是未签名安装包，只适合本机验收。轻量包加 `-Light`（`Compile-Installer.ps1 -Light`，暂存也用 `Prepare-PackageFiles.ps1 -Light`）跳过词库和出厂配置，安装时也不会删除本机已有词库。`tests/tools/installer_entry.ps1` 用替身覆盖了相同的六段顺序。

## 签名与发布

For a release package, run `Sign-PackageBinaries-SimplySign.ps1` after staging. It selects the connected Certum code-signing certificate, signs every EXE/DLL under `server_exe` and `tsf_dll` in one signtool invocation, then verifies the certificate and trusted timestamp on every file. The local test-certificate script (`Sign-PackageBinaries-Local.ps1`) is separate and must not be used for public releases. After Inno Setup creates the outer installer, run `Sign-Installer-SimplySign.ps1` to apply and verify the same release signature and timestamp to the installer itself.

For the complete release sequence, use `Package-SimplySign.ps1`. It builds both architectures, stages the package, signs payloads, compiles Inno Setup with `Compile-Installer.ps1`, signs the outer installer, and writes `msime-windows-<edition>-<version>-symbols.zip` for the same build beside it in `Output` with `Collect-Symbols.ps1`; it never installs or modifies CI state. The release `release-windows.yml` publishes carries CI's unsigned installer, and the rolling `windows-symbols` release carries CI's symbols; neither matches the locally built binaries, so the maintainer replaces both with the ones this script wrote. The installer is built on Windows, not in CI: the Windows CI job and `release-windows.yml` both stop at the MinGW cross build.

`msime_setup.iss` requires Inno Setup 6.6 or newer. It installs the 32-bit TSF DLL under `{commonpf32}\<install_dir>\msime_v<version>\` and the 64-bit (on Windows on Arm, Arm64X) TSF DLL, with the host and runtime DLLs it loads from its own directory, under `{sys}\IME\<install_dir>\msime_v<version>\` (`MySystemTipDir`), each with the `regserver` flag so the TIP is registered; Counter-Strike 2's Trusted Mode refuses foreign DLLs outside the Windows system directory, so a 64-bit TIP under Program Files never loads there. The System32 copies carry `uninsrestartdelete`, and because a Setup compiled with Inno Setup 7 is a 32-bit process whose `[Code]` file functions and `Exec` are redirected to SysWOW64 (Inno Setup 6 bypasses redirection there in 64-bit install mode), the script probes and cleans that directory only through `cmd.exe` and a 64-bit PowerShell launched with `ExecNativeSys`, which is `ExecWithNativeSysDir` under 7 and `Exec` under 6; stopping the Server by path goes through the same macro. It puts the Server package under `{commonpf64}\<install_dir>\server`, writes `VersionDir`, `ServerPath` and `DataDir` under `HKLM\<registry_key>` (both from the edition's `platforms.windows` section; full uses `metasequoiaime-full` and `Software\Metasequoia\MetasequoiaIME-Full`, while `metasequoiaime` and `Software\Metasequoia\MetasequoiaIME` belong to msime-windows), and copies `config.toml` only when it does not already exist so an upgrade never overwrites user configuration. `THIRD_PARTY_NOTICES.txt` and `LICENSE.txt` ship with the package, as GPLv3 sections 4 and 6 require. `ISCC /DLightPackage=1` produces the light package, which omits the bundled dictionaries. PDB and `.ilk` files stay in the staging folders but are not installed; `Collect-Symbols.ps1` packs the staged PDBs, plus the host DLL's from each architecture's build output, into `msime-windows-<edition>-<version>-symbols.zip`, and an upgrade deletes the PDBs older packages left in the Server folder.

Build the native WinUI 3 settings project before staging. `Prepare-PackageFiles.ps1` accepts the native settings executable through `-DesktopExecutable` (defaulting to `target/windows-<edition>/x64/bin/msime-client-settings.exe`); the consolidated build stages it beside the Server automatically. A missing settings binary is rejected before resetting the existing staging directories. The WinUI 3 settings window is native and does not need WebView2.

词库升级先按打包时的 SHA-256 比对已安装资源：内容相同则保留，内容不同、缺失或无法读取则正常替换。Restart Manager 同时检查 DB、BIN 与 DAT 占用；资源确实变化时需要保存文档并正常关闭持有旧词库的应用，不能强制结束用户进程。实际文件锁回归使用合成内容：

```powershell
./platforms/windows/installer/tests/resource-upgrade.ps1 -IsccPath 'C:/Program Files (x86)/Inno Setup 6/ISCC.exe'
```

在构建机加 `-ArtifactDirectory <目录> -CompileOnly` 可生成小型验收安装器，再将该目录的 `resource-upgrade.exe` 和测试脚本复制到 Win7，以 `-ArtifactDirectory <目录> -RunOnly` 验证系统自带 PowerShell 2 下的相同锁定资源保留、不同资源替换、缺失资源安装和不同锁定资源拒绝跳过。
